# Предварительные результаты разработки

## 1. Описание проделанной работы для доклада

На текущем этапе дипломного проекта разработана основная часть веб-информационной системы для управления автопарком, строительными объектами, персоналом и сервисным обслуживанием техники.

В системе реализована авторизация пользователей и разделение учетных записей по ролям. Предусмотрены роли администратора, модератора, механика и водителя. В зависимости от роли пользователь получает доступ к определенным разделам и операциям. Администратор имеет возможность управлять пользователями, а модератор может выполнять основные рабочие операции с автопарком, водителями, механиками, строительными объектами и сервисными заявками. Механики и водители работают с системой преимущественно в режиме просмотра.

Разработан пользовательский интерфейс панели управления. В приложение включены разделы для работы с пользователями, водителями, механиками, автопарком, сервисными событиями, строительными объектами, уведомлениями и профилем пользователя. Интерфейс построен как единая административная панель с боковой навигацией, таблицами, формами, диалоговыми окнами, статистическими карточками и уведомлениями.

Реализован модуль управления пользователями. Он позволяет просматривать список пользователей, создавать новые учетные записи, изменять данные пользователей, назначать роли, блокировать и удалять учетные записи. Для контроля действий предусмотрен журнал аудита, в котором фиксируются операции входа, выхода, создания, изменения, блокировки и удаления пользователей.

Отдельно реализованы разделы для водителей и механиков. В них предусмотрено назначение пользователей на соответствующие роли, хранение водительских категорий, специализаций механиков и документов. Система позволяет отслеживать активных водителей и механиков, а также пользователей, которые еще не назначены на соответствующую должность.

Разработан модуль автопарка. В нем можно вести учет техники, хранить сведения о марке, модели, государственном номере, статусе, примечаниях и закрепленном водителе. Предусмотрены операции добавления, редактирования, удаления техники и закрепления водителя за транспортным средством. Изменения по автопарку фиксируются в отдельном журнале аудита.

Реализован модуль строительных объектов. Пользователь может создавать объекты, указывать вид работ, адрес, координаты, сроки выполнения, примечания и статус завершения. Для объектов предусмотрено назначение техники, просмотр активных и архивных объектов, а также отображение объектов на карте. Операции по объектам фиксируются в журнале аудита.

Создан раздел сервисного обслуживания. Он позволяет учитывать сервисные события по технике: техническое обслуживание, осмотр, ремонт, страхование и диагностику. Для каждой заявки можно указать транспорт, тип события, статус, срок выполнения, пробег, ответственного механика и примечания. В интерфейсе отображается статистика по запланированным, выполняемым, просроченным и завершенным сервисным событиям.

Также реализован механизм уведомлений. Пользователи могут просматривать уведомления и отмечать их как прочитанные. Для администраторов и модераторов доступны уведомления, связанные с действиями в системе, а для остальных пользователей отображаются системные и служебные уведомления.

На данный момент проект уже содержит основные функциональные модули, структуру базы данных, клиентское приложение, серверное API, авторизацию, ролевую модель, журналы аудита и интерфейс для работы с ключевыми сущностями системы.

## 2. Техническое описание текущей реализации

### Общая архитектура

Проект реализован как full-stack веб-приложение и состоит из двух основных частей:

| Часть проекта | Каталог | Назначение |
| --- | --- | --- |
| Клиентское приложение | `next-app` | Интерфейс пользователя на Next.js и React. |
| Серверное приложение | `backend` | REST API на NestJS. |
| База данных | PostgreSQL через Prisma | Хранение пользователей, ролей, техники, объектов, сервисных событий, уведомлений и журналов аудита. |

Клиентская часть взаимодействует с серверной через API по адресу `http://localhost:4000/api`. Для запросов используется единый слой `lib/api.ts`, который добавляет JWT-токен из cookie в заголовок `Authorization`.

### Используемые технологии

| Направление | Технологии |
| --- | --- |
| Frontend | Next.js, React, TypeScript |
| UI | shadcn/ui, Radix UI, Tailwind CSS, Hugeicons |
| Таблицы и визуализация | TanStack Table, Recharts |
| Backend | NestJS, TypeScript |
| Авторизация | JWT, Passport JWT, bcrypt |
| База данных | PostgreSQL, Prisma ORM |
| Валидация данных | class-validator, class-transformer |
| Загрузка файлов | Multer |
| Тестирование backend | Jest, Supertest |

### Реализованные роли

Роли определены в схеме Prisma через перечисление `UserRole`:

| Роль | Значение |
| --- | --- |
| Администратор | `admin` |
| Модератор | `moderator` |
| Механик | `mechanic` |
| Водитель | `driver` |

На frontend роль пользователя обрабатывается через `RoleProvider`. В интерфейсе используются флаги:

| Флаг | Условие | Назначение |
| --- | --- | --- |
| `isAdmin` | роль `admin` | Доступ к разделу пользователей. |
| `isModerator` | роль `moderator` | Определение роли модератора. |
| `canEdit` | `admin` или `moderator` | Отображение операций создания, редактирования, удаления и назначения. |
| `canViewAudit` | `admin` или `moderator` | Отображение журналов аудита. |

На backend все основные контроллеры защищены `JwtAuthGuard`. JWT payload содержит идентификатор пользователя, имя пользователя и роль.

### Реализованные функции авторизации

Авторизация реализована через связку `username` и `password`. Пароль проверяется через `bcrypt`. После успешного входа сервер:

1. Проверяет существование пользователя.
2. Проверяет пароль.
3. Проверяет, что пользователь не заблокирован.
4. Создает JWT-токен.
5. Сохраняет сессию в таблицу `Session`.
6. Обновляет признак `isOnline`.
7. Записывает событие входа в `AuditLog`.

При выходе из системы сессия удаляется, пользователь помечается как offline, а действие записывается в журнал аудита.

### Реализованные функции автопарка

В модуле автопарка реализованы:

1. Получение списка техники.
2. Создание новой единицы техники.
3. Редактирование марки, модели, государственного номера, статуса, примечаний.
4. Закрепление и открепление водителя.
5. Удаление техники.
6. Проверка уникальности государственного номера.
7. Формирование журнала аудита по операциям с техникой.

Статусы техники преобразуются в представление интерфейса: активная, резервная или в ремонте.

### Реализованные функции строительных объектов

В модуле строительных объектов реализованы:

1. Получение активных объектов.
2. Получение архивных объектов.
3. Получение детальной информации по объекту.
4. Создание объекта.
5. Редактирование объекта.
6. Завершение объекта.
7. Удаление объекта.
8. Назначение техники на объект.
9. Снятие техники с объекта.
10. Получение списка доступной техники.
11. Ведение журнала аудита по действиям с объектами.

На frontend дополнительно реализовано отображение объектов на карте и разделение объектов на активные и архивные.

### Реализованные функции сервиса

В модуле сервисных событий реализованы:

1. Получение списка сервисных событий.
2. Фильтрация событий по транспорту, статусу, типу и поисковой строке.
3. Получение статистики по статусам.
4. Создание сервисной заявки.
5. Редактирование сервисной заявки.
6. Удаление сервисной заявки.
7. Назначение ответственного механика.

В интерфейсе отображаются карточки статистики и предупреждение о просроченных заявках.

### Реализованные функции уведомлений

Модуль уведомлений поддерживает:

1. Получение списка уведомлений.
2. Подсчет непрочитанных уведомлений.
3. Отметку одного уведомления как прочитанного.
4. Отметку всех уведомлений как прочитанных.
5. Фильтрацию категорий уведомлений по роли пользователя.

Для администраторов и модераторов доступны уведомления категорий `system`, `security` и `action`. Для механиков и водителей доступны уведомления категорий `system` и `security`.

### Реализованный аудит

В проекте предусмотрены отдельные журналы аудита для разных областей:

| Журнал | Что фиксируется |
| --- | --- |
| `AuditLog` | Вход, выход, создание, изменение, блокировка, удаление пользователей. |
| `DriverAuditLog` | Назначение водителя, изменение категорий, загрузка и удаление документов. |
| `MechanicAuditLog` | Назначение механика, изменение специализаций, загрузка и удаление документов. |
| `FleetAuditLog` | Создание, изменение, удаление техники, смена статуса, закрепление и открепление водителя. |
| `ConstructionSiteAuditLog` | Создание, изменение, удаление, завершение объекта, назначение и снятие техники. |

Журналы аудита используются для контроля изменений и отображаются в интерфейсе для пользователей с правами администратора или модератора.

### Текущее состояние тестирования

В backend настроена инфраструктура тестирования:

| Инструмент | Назначение |
| --- | --- |
| Jest | Unit- и интеграционное тестирование. |
| Supertest | Проверка HTTP API. |
| `test:e2e` | Запуск end-to-end тестов NestJS. |
| `test:cov` | Формирование отчета о покрытии тестами. |

В проекте присутствует базовый e2e-тест NestJS. Для дальнейшей проверки рекомендуется расширить тестирование сценариями авторизации, разграничения прав доступа, CRUD-операций, назначения техники на объект, закрепления водителя и обработки ошибок.

## 3. Что можно доработать далее

Для завершения проекта рекомендуется выполнить следующие работы:

1. Добавить серверную проверку ролей через `RolesGuard` и декоратор `@Roles`.
2. Расширить e2e-тесты для критичных API-маршрутов.
3. Проверить сценарии работы всех ролей в интерфейсе.
4. Подготовить итоговые UML-диаграммы и ER-диаграмму базы данных.
5. Описать пользовательские сценарии и результаты тестирования в пояснительной записке.
6. Подготовить скриншоты основных экранов приложения для приложения к диплому.
